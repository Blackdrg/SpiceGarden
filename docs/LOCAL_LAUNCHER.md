# Local Launcher for SpiceGarden

## Overview
`run.cmd` is a single‑command entry point that starts the full SpiceGarden development stack on **Windows**. It delegates the heavy lifting to a Node orchestrator (`scripts/dev/run-local.js`).

## Usage
```bat
# Core stack (backend + web apps + infra)
.\run.cmd

# Full stack (core + observability services)
.\run.cmd --full

# Infrastructure only (Docker containers)
.\run.cmd --infra

# Health check only (no start)
.\run.cmd --check

# Stop everything
.\stop.cmd
```

## What it does
1. **Prerequisite validation** – checks for `node`, `npm`, `docker`, and `docker compose`.
2. **Docker infrastructure** – brings up `postgres`, `redis`, `mongo` (and optional observability services in `--full`).
3. **Backend** – runs `npm --workspace apps/backend run dev` in its own terminal.
4. **Frontend apps** – runs the `dev` scripts of `customer-web`, `restaurant-dashboard`, and `super-admin` in separate terminals.
5. **Health checks** – waits for services to become reachable (ports 3001‑3004, plus infra ports).
6. **Logging** – each service writes its stdout/stderr to `logs/<service>.log`.
7. **Summary** – prints URLs of all running services and automatically opens the three core web apps in the default browser.

## Log files
All logs are stored under the `logs/` folder:
- `backend.log`
- `customer-web.log`
- `restaurant-dashboard.log`
- `super-admin.log`
- `launcher.log` (output of the orchestrator itself)

## Stopping the stack
`stop.cmd` shuts down Docker containers (`docker compose down`) and attempts to close any command windows opened by the launcher.

## Known limitations
- The launcher assumes the default ports defined in the repository (`3001‑3004` for services, `3000` for Grafana, `9090` for Prometheus, `9200` for OpenSearch, `9093` for Alertmanager). If you change these in `compose.dev.yaml` you will need to update the script accordingly.
- Observability services are optional; they are only started with the `--full` flag.
- Mobile apps (`delivery-partner`, etc.) are not started automatically – they can be launched manually if needed.

## Tips
- Run `npm run dev:local` (or the other shortcuts added to `package.json`) as a convenient alias.
- If a service fails to start, inspect its log file under `logs/` for details.
- The script is idempotent – re‑running `run.cmd` will not duplicate containers; it will detect already‑running services.
