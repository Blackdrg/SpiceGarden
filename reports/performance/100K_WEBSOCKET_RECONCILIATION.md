## 2. Forensic Audit of the WebSocket Rate-Limiter

A critical concern is whether the WebSocket gateway rate-limiting was altered, disabled, or bypassed to permit benchmark traffic, potentially compromising production security.

### Codebase Implementation
Inspecting [`apps/backend/src/infra/tracking/tracking.gateway.ts`](file:///c:/Users/mehta/Desktop/SpiceGarden/apps/backend/src/infra/tracking/tracking.gateway.ts#L20-L21) and [`apps/backend/src/services/restaurant/kds.gateway.ts`](file:///c:/Users/mehta/Desktop/SpiceGarden/apps/backend/src/services/restaurant/kds.gateway.ts#L14-L15):

```typescript
const WS_RATE_LIMIT_MAX = Number(process.env.WS_RATE_LIMIT_MAX || 10);
const WS_RATE_LIMIT_WINDOW_MS = Number(process.env.WS_RATE_LIMIT_WINDOW_MS || 60000);
```

### Connection Evaluation Logic
```typescript
private isConnectionAllowed(client: Socket): boolean {
  const now = Date.now();
  const forwardedFor = client.handshake.headers['x-forwarded-for'];
  const forwardedIp = Array.isArray(forwardedFor) ? forwardedFor[0] : forwardedFor?.split(',')[0]?.trim();
  const key = forwardedIp || client.handshake.address || client.id;
  const current = this.connectionAttempts.get(key);

  if (!current || now >= current.resetAt) {
    this.connectionAttempts.set(key, { count: 1, resetAt: now + WS_RATE_LIMIT_WINDOW_MS });
    return true;
  }

  if (current.count >= WS_RATE_LIMIT_MAX) {
    this.logger.warn(`Rejected websocket connection from ${key}: rate limit exceeded`);
    return false;
  }

  current.count += 1;
  this.connectionAttempts.set(key, current);
  return true;
}
```

## 3. Configuration & Security Assessment

| Configuration Level | `WS_RATE_LIMIT_MAX` | `WS_RATE_LIMIT_WINDOW_MS` | Operational Behavior | Security Implication |
| :--- | :--- | :--- | :--- | :--- |
| **Default Configuration** | `10` | `60,000` (1 min) | Max 10 connection attempts per IP/minute | Protects against DoS / socket exhaustion |
| **Production Recommended** | `30` | `60,000` (1 min) | Accommodates multi-tab user reconnections | Strong anti-abuse baseline |
| **Load-Test Configuration** | `10,000` (via env) | `60,000` (1 min) | Accommodates thousands of VUs per generator node IP | Required for synthetic load generation |
| **Maximum Safe Production** | `50` | `60,000` (1 min) | Protects gateway node memory from connection flood | Prevents DoS attacks on socket servers |

### Audit Finding
1. **Production Security Control Preserved:** The hardcoded defaults in code remain secure (`10` connections per minute per IP).
2. **Environment-Driven Configuration:** The rate limit is dynamically configurable via `WS_RATE_LIMIT_MAX` environment variable. The security mechanism was not disabled in application source code.
